## 1. 리액트의 시작



## 1.1 왜 리액트인가?


자바스크립트로도 규모가 큰 애플리케이션을 만들 수 있게 되었다.


그럼 이 애플리케이션 구조를 관리하려면 어떻게 해야 할까?


해결을 위한 수 많은 프레임워크 : Angular, Backbone.js, Derby.js, Ember.js, Ext.js, Knockback.js, Sammy.js, PureMVC, Vue.js

	- MVC(Model-View-Controller) 아키텍처
	- MVVM(Model-View-View Model) 아키텍처
	- MVW(Model-View-Whatever) 아키텍처

MVC, MVVM, MVW 등과 같은 여러 구조가 지닌 공통점

	- 모델과 뷰가 있다.
		- 모델(Model) : 애플리케이션에서 사용하는 데이터를 관리하는 영역
		- 뷰(View) : 사용자에게 보이는 부분
		- 컨트롤러(Controller) : 모델 데이터를 조회하거나 수정하고, 변경된 사항을 뷰에 반영

수정사항을 반영하는 과정에서 보통 뷰를 변형한다.

	- 페이스북 팀이 고안한 아이디어
		- 어떤 데이터가 변할 때마다 어떤 변화를 줄지 고민 X
		- **기존 뷰를 날려 버리고 처음부터 새로 렌더링**
			- 장점
				1. 애플리케이션 구조 간단
				2. 작성해야 하는 코드 양 감소
			- 단점
				1. CPU 점유율 크게 증가
				2. 메모리 사용량 증가
				3. 인풋 박스에 입력 시 새로 렌더링되면서 끊김 현상 발생

> 💡 최대한 성능을 아끼고 편안한 사용자 경험(user experience)을 제공하면서 구현하고자 개발한 것이 바로 리액트(React)입니다.

이를 파악하려면 `초기 렌더링`과 `리렌더링` 개념을 이해해야 한다.

- 초기 렌더링 : 리액트 컴포넌트 최초 실행
- 리렌더링 : 컴포넌트의 데이터 변경


#### 1.1.1.1 초기 렌더링


어떤 프레임워크든 초기 렌더링이 필요하다.


react

	- render()
		- 컴포넌트가 어떻게 생겼는지 정의
			- html 형식의 문자열 반환 X
			- 뷰가 어떻게 생겼고 어떻게 작동하는 지에 대한 정보를 지닌 객체 반환

컴포넌트 내부에는 또 다른 컴포넌트들이 들어갈 수 있다.


이때 render 함수를 실행하면 그 내부에 있는 컴포넌트들도 재귀적으로 렌더링한다.


최상위 컴포넌트의 렌더링 작업이 끝나면


지니고 있는 정보들을 사용하여 HTML 마크업을 만들고,


이를 우리가 정하는 실제 페이지의 DOM 요소 안에 주입


컴포넌트를 실제 페이지에 렌더링할 때는 분리된 두 가지 절차를 따르는데요.


먼저 문자열 형태의 HTML 코드를 생성한 후 특정 DOM에 해당 내용을 주입하면 이벤트가 적용됩니다.



#### 1.1.1.2 조화 과정


리액트 라이브러리에서 중요한 부분인 **업데이트**를 어떻게 진행할까?


리액트에서 뷰을 업데이트할 때

	- 업데이트 과정을 거친다 (X)
	- 조화 과정(reconciliation)을 거친다 (O)

뷰가 변형되는 것처럼 보이지만, 사실은 새로운 요소로 갈아 끼우기 때문!


→ 이 작업도 render 함수가 함



#### 리액트의 뷰 업데이트 과정

1. 데이터가 업데이트됨
2. 컴포넌트는 새로운 데이터를 가지고 render 함수를 다시 호출
3. 데이터를 지닌 뷰가 생성됨
4. 이때 render 함수가 반환한 객체를 곧바로 DOM에 반영X
5. 이전에 render 함수가 만들었던 컴포넌트 정보와 비교
	- javascript를 사용하여 최소한의 연산으로 비교
6. 둘의 차이만을 최소한의 연산으로 DOM 트리 업데이트
